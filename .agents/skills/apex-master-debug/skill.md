## Reactive Mode (8-Phase Protocol)

**Failures to avoid**:
- ❌ Editing before viewing → Hallucination risk. Always use terminal/view tools first.
- ❌ "Let me try this" loops → Prohibited. Evidence must be 100% proven before editing.

**Correct approach**:
1. **Harvest**: `cat src/broken_module.ts` or run tests via terminal.
2. **Temporal RCA**: Trace the error backward to the explicit origin point.
3. **Blast Radius**: `grep` for all dependencies linked to the failure point.
4. **Simulation**: Mentally execute the fix.
5. **Pre-flight**: Write the failing regression test.
6. **Surgical Fix**: Apply the ONE edit.
7. **Closure Shield**: Verify tests pass.

## Predictive Mode (Omega Scan)

**Correct approach**:
1. Execute terminal commands to hunt vulnerabilities (e.g., `grep -rn "catch.*{}" src/`).
2. Score risks based on: Severity(1-4) x Likelihood(1-4) x BlastRadius(1-4).
3. If score >= 30, generate proactive patch immediately.
