# User Operating Model
**Version:** 1.1.0 | **Date:** 2026-05-26 | **Author:** Lead AI Co-Founder | **Status:** Audited & Active

**Confidence:** High; based on repeated observation of high-leverage execution loops, automated testing runs, and strict governance check resolutions on `2026-05-26`.

## Stable Tendencies Observed

- **Prefers Systems over One-Offs:** Designing frameworks and database architectures rather than quick hardcoded fixes.
- **Values Compounding Memory:** Wants corrections and lessons permanently written to local memory files.
- **values Signal Density:** Decisive, professional, and clear executive-level updates with high-fidelity technical depth.
- **Low Noise Preference:** Extremely dislikes generic chat responses, motivational filler, or soft maintenance-heavy architectures.
- **Pragmatic Adaptation:** Wants code aligned strictly with real capabilities and platform limitations, never fictitious features.
- **Strict Compliance Guardrails:** Values 100% adherence to branch protection rules (e.g. RFC links) and strict SQL schema rules (e.g. additive-migration linter checks).

## Output Bias

- **Lead with Decisions:** Front-load conclusions and exact status.
- **Be Decisively Grounded:** Explicitly separate verified operational status from unverified claims.
- **Maintain Canonical Order:** Favor structured repositories, blueprints, and clean commit protocols.
- **Zero Filler Policy:** Avoid conversational transitions, motivational summaries, or repetitive apologies.
- **High Leverage Action:** Propose minimal, highly deterministic code edits that solve system-level issues permanently.

## Quality Signals

- **Excellent:** Type-safe components, strict TypeScript mode, low-noise shell output, preceding-line comments for linter exceptions, direct CLI remote deployment.
- **Poor:** Hardcoded mock statuses, duplicate documentation folders, missing RFC links for database/edge function PRs, or verbose conversational summaries.

## Promotion Rules

Promote a new rule to durable memory only if it is:
- Explicitly stated as a stable preference.
- Repeated across multiple interactions.
- A correction with broad future applicability.
