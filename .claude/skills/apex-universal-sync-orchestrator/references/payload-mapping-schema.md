# Payload Mapping Schema Format

Defines how `sync_payload.py` maps external application JSON fields into
APEX-OmniHub state vectors.

## Structure

```json
{
  "schema_version": "1.0",
  "source_system": "salesforce",
  "field_mappings": {
    "<target_field>": {
      "source_field": "<source_field_in_data_payload>",
      "type": "string | integer | float | boolean",
      "optional": false,
      "default": null
    }
  }
}
```

## Required Payload Fields

Every external payload passed to `sync_payload.py` must include:

| Field | Type | Description |
|---|---|---|
| `source_system` | string | Identifier for the originating application (e.g., `salesforce`, `hubspot`) |
| `sync_timestamp` | string/number | ISO-8601 or epoch timestamp of the sync event |
| `data_payload` | object | Nested object containing the actual field data to be mapped |

## Field Mapping Rules

- `source_field`: The key inside `data_payload` to read from. Defaults to the target field name if omitted.
- `type`: Target type for coercion. Supported: `string`, `integer`, `float`, `boolean`.
- `optional`: If `true`, a missing source field uses the `default` value instead of failing.
- `default`: Value used when the field is optional and absent. Can be `null`.

## Example

```json
{
  "schema_version": "1.0",
  "source_system": "salesforce",
  "field_mappings": {
    "account_name": { "source_field": "AccountName", "type": "string" },
    "revenue":      { "source_field": "AnnualRevenue", "type": "float" },
    "active":       { "source_field": "IsActive", "type": "boolean", "optional": true, "default": false }
  }
}
```

## OmniBoard Integration Notes

The normalized output always includes `omni_id` (format: `{source_system}_{epoch_ms}`)
which OmniBoard uses for deterministic deduplication on re-sync. Do not
manually set `omni_id` — it is generated by `sync_payload.py` from
`source_system` and `sync_timestamp`.

OmniBoard is strictly for application integration and onboarding workflows.
Do not use this schema for client-facing data pipelines or direct DB migrations.
